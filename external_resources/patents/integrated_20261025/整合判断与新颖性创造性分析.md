# 两份交底书的整合判断与新颖性、创造性分析

分析日期：2026年10月25日。对应交付稿为《一种基于交互失效邻域反馈的自动驾驶迭代测试方法》。本说明供发明人和代理师确定申请方案；两份源DOCX及此前申请材料均保持原样。

## 1 整合结论及取舍

可以形成一份技术关系更连贯的交底书，但“内容更多”不直接带来新颖性或创造性。两稿在工程上可分别部署，也存在共同的核心处理对象：可恢复的交通实例、受控局部变更、失效与成功端点、策略执行结果及后续测试资源。以这些对象贯穿发现和版本迭代，比继续把“生成与搜索”“版本比较与调度”刻意写成互不依赖的创新，更符合当前项目的实施结构。

本次整合选择的技术问题是：怎样让发现阶段实际执行的局部输入关系，在策略更新后继续用于识别未解决失效和局部回归，并决定下一次仿真从哪个实例出发、改变哪类行为。相应保护主线为：**可恢复的响应式交互 → 同策略单组风险比较及邻域保留 → 当前基准确认和固定成员的同输入版本比较 → 持续失效、回归失效分别归一化 → 区域份额与行为组概率共同生成下一轮输入。**

这里保留两种不同的比较。横向比较在同一策略下改变局部背景输入，用于搜索方向和邻域形成；纵向比较对同一完整输入更换策略，用于版本反馈。它们共享实例记录，但固定与变化的对象不同，不能用一次风险差同时解释环境变化和策略变化。这一关系已写入正文和图2占位说明。

| 原稿内容 | 整合处理 | 技术理由 |
| --- | --- | --- |
| 自然事件、固定条件与显式随机输入 | 保留为局部比较和跨版本恢复基础；允许生成事件实例化后固定 | 与实际输入对应关系直接相关，也与当前生成交通实例的代码相容 |
| 参考生成、背景响应和机动承接 | 保留实施细节，具体模型放在从属层次 | 保证版本动作的后果能进入实际交通执行；不把已有响应仿真整体作为独占创新 |
| 单组风险反馈 | 与相反结果邻域形成共用有效执行记录 | 既控制后续变化方向，也为后续版本检查提供相邻条件 |
| 成功邻点、当前标签、固定区域和分组反馈 | 合并为版本迭代的连续处理 | 使局部成功条件能够产生回归反馈，并使区域统计对应固定比较对象 |
| 风险分层、区域划分与来源代表限制 | 作为可用实施方式 | 分层搜索和多样性控制已有工程基础；区域是经验测试组织单位 |
| 严格失效域连通确认、目标域推荐、最大流及跨域累计来源额度 | 不进入主保护链；共享来源额度保留简要可选接口 | 这些内容形成另一套覆盖与容量优化问题；全部强制加入会增加必要特征，并非当前邻域反馈链的实施前提 |
| 模型修复或训练 | 保留外部策略更新接口 | 本次保护测试如何随版本变化，不扩张到所有训练方法和能力保持机制 |

新稿采用7个一级章节，具体方案保留5个有实施必要的二级小节。背景、保护内容和技术效果以连贯段落展开；不逐项复述实验流水。正文保留3张既有PNG工程图和2处逻辑附图占位，没有新绘制、虚构实验图，也未生成SVG或交付PDF。

新颖性方面，在本次核对范围内，尚未确认单一文件直接、无歧义公开整合稿所述全部连续处理关系，因而可以围绕这一具体组合继续组织独立权利要求。该判断依赖最终权利要求包含实质关系，不能从“尚未检索到同名方案”推得。

创造性方面，最需要认真处理的是边界优先选择文献与GENBO、GUARD或版本差分方法的组合。当前风险不在于某一术语是否相同，而在于上述组合是否会自然得到邻域保存、版本反馈及下一轮分配。两个条件比例的公式本身较为直接；只增加非负加权或更换分母，难以承担整项申请的创造性。较有针对性的论证应落在：一次经输入校验的单组执行如何同时产生搜索依据和可恢复邻域；当前基准及固定区域如何使局部版本反馈可用；两类反馈如何与组概率共同控制实际仿真调用。其技术效果需要对应输入一致性、结果转移和执行记录，而非一般“提高效率”的表述。

[现行《专利审查指南》修改决定](https://www.cnipa.gov.cn/art/2025/11/14/art_99_202568.html)明确要求针对权利要求限定的技术方案整体评价创造性，并将对现有技术作出贡献的特征写入权利要求。本次据此把保护重点由“覆盖更多失效域”转为前述可实施的数据与执行关系。整合能够使技术贡献表达集中；是否达到创造性要求仍需代理师结合检索和最终申请文本判断，现有材料不支持量化授权概率。

本次只读取代码和已有实验，未新增训练、闭环仿真或模型选择，未修改工程实现。交底书是对已披露构思作可实施的整合，并非宣称代码已经实现全部约束。

首轮正式比较以相同冻结初始策略和每方法5,000次实际调用进行。主搜索去重碰撞为随机抽样160、风险子集215、引导原型450，分别含2、3、1个初始碰撞。排除初始碰撞后为158、212、449；引导原型另有500次分支检查，其中19次碰撞命中，计入总调用但不计入450项。该结果支持当前原型的定向失效发现，不能证明整合稿全部机制各自带来增益，也不能将450项等同于450个独立来源或不同失效域。

第二轮恢复115个原档案端点，记录63个持续失效、43个失效解除、1个回归失效和8个持续成功。整体比例为63/106及1/9，证实同一档案中两类测试需求可以同时存在；实际分配仍按当前分支中的成员计算。数据来源为`preparation/round_one_search_comparison.json`及`preparation/guided_round_two_replay_acceptance.json`，输入和相关代码校验值列入`support/source_manifest.json`。

项目还完成了模型修复及独立留出评价。长尾留出的碰撞由61降至40/2,000，但同预算三种修复来源之间的优势尚未成立，自然集合也应分别解释。这些结果不负责证明本次固定事件、冻结区域及邻域反馈组合的增益，所以没有加入交底书的核心效果叙事。其完整结论保留在原工程记录中，没有改写或删除。
