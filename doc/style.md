# 编码规范

- 使用 Python 3，缩进为 4 个空格，遵循 PEP 8 的基本布局。
- 导入顺序：标准库、第三方库、本项目模块。
- 命名：类用 `PascalCase`；函数、变量用 `snake_case`；常量用 `UPPER_CASE`。
- 不添加无必要的 CLI 参数；默认实验参数要写在脚本常量或配置文件中,从而使得代码可以直接运行。
- 鼓励代码简洁实现：优先使用直接可读的函数；不要为了兼容而引入复杂抽象或多层间接调用。
- 不保留废弃 wrapper、旧兼容分支、无意义 fallback、未使用字段、未使用配置、未使用函数和未使用脚本；发现后应直接删除，而不是继续转发或隐藏在兼容层后。
- 注释只解释不明显的设计或约束，避免重复代码含义。避免无意义的解释,不要造词,而是使用易懂简洁的用词
- 不使用空 `except`；错误应直接暴露或带有明确上下文。
- 不提交 `__pycache__`、大型可再生成结果和临时文件。
- 必要的被测模型、复现权重及配套学习状态应保留；大型文件存放到 `/media/hp/DATA/nuplan_workspace/FITWMAMS_models/`，工程原路径通过符号链接访问，并记录来源与 SHA256。迁移时先复制并验证，再替换原路径。不能仅因暂未使用或可以重新下载就删除模型。
- 在不破坏现有功能和配置字的前提下，删除冗余代码、重复逻辑、无用接口和临时缓存。
- 对本项目做必要的整理,鼓励代码的简洁和可读,安全删除确认无效的历史分支实验代码和测试结果,注意文件组织和命名, 注意文件和文件夹命名的正确规范合适,并必要性的合并减少文件数量
- 减少防御性编程和冗余,尽量不要用数字参与文件的命名
- 严禁超前设计，严禁过度工程，严禁防御未出现的错误，严禁向后兼容，严禁使用 胶水代码 掩盖需要修剪的实现和旧路径
- 每个项目一级目录保留一个独立的 `README.md`，说明该目录的代码、数据或结果及主要入口。更深层目录只在确有独立协议或说明需求时编写 README，不要求逐层设置；具体指标以原始报告为准，避免重复抄写。
