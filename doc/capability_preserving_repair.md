# 全量可用数据驱动的风险测试与能力保持修复

2026-10-25。本文档规定下一版方案：**原任务材料全量处理，事故材料全量申请纠正，训练按祖先均衡，并以独立验证控制能力回退。** 本次交付仅为设计文档；数据扩充、训练约束、补标和新版评价尚待实施，不修改训练代码或配置，不启动实验。

本方案替代此前原任务训练截断为 10,000 个场景、事故输入截断为 128 个的设计。[既有方案与实验记录](risk_stratified_repair.md)保留，用于查阅已完成的两轮实验及历史结果；其中较早的后续预算不作为本版执行设置。

## 1．目标与固定设置

目标是将找到的失效用例转化为正确学习材料，增强同一个 ADS 的长尾应对能力，同时保持已有驾驶能力。每个 ADS 最终交付一份固定增强权重，在 highway-env 与 nuPlan 使用各自必要的输入和执行适配，模型参数一致。

方法流程为：

**冻结长尾分布 → 一次风险测试 → 全量事故纠正材料与成功保持材料 → 受约束的局部微调 → 一次有限状态补标 → 开发验证与模型接纳 → 冻结后独立评价。**

固定设置如下：

- 先在 Diffusion Planner（DP）上实施，使用现有 `conda activate tread` 环境，单实验种子为 `20260926`。
- 保留全部 **2,964 个 highD 尾部事件**及既有长尾 Flow、Diffusion、世界模型资产；道路、车辆类别、NPC 参数和接管机制不变。
- 三方法均从同一官方 DP 初始部署模型 \(\pi_0\) 开始；记录源码、配置、归一化与权重哈希。沿用 5 Hz 决策、25 Hz 物理执行及因果观测。
- 每方法进行一次 **5,000 次完整闭环搜索**，初始先验、接受和拒绝的条件提议及搜索检查均计费。搜索路径结束后从先验重启以完成等预算比较。
- 搜索后进行一次修复，不在修复后启动第二轮 5,000 次搜索。修复内部的两段更新和一次补标不另计为一轮搜索。
- 搜索风险评分沿用现有安全包络定义，真实失效仍为自车碰撞或驶出道路。主要评价碰撞率，停车、进度及其他安全记录分别报告。
- 本版不以搜索分支数论证充分的多失效域覆盖，也不通过自适应搜索命中率估计原分布事故概率。

### 2.1 原任务材料全量处理

现有清单位于 `/media/hp/DATA/nuplan_workspace/preparation/retention/scenes.json`。训练角色 `replay` 含 2,000 个 selected 和 11,066 个 reserve；开发角色 `development` 含 200 个 selected 和 2,940 个 reserve。两组分别来自 605 和 153 个会话，会话无交叉。

全量处理指完整遍历每个角色的 selected 与 reserve，按日志和场景 token 去重，逐例形成有效特征或明确的排除记录，不再达到固定数量后停止。保留官方输入、坐标、归一化和真实未来标签。训练与验证仍按原日志／会话用途隔离，开发 reserve 不转给训练。

截至本次核对，DP 已完成 2,000 个训练场景及 200 个开发场景的有效预处理；已有记录中，训练候选有 **84 个**、开发候选有 **11 个**因缺少有效原生路线而排除。这些不是全量源池的最终排除数量。因此，13,066／3,140 是待全量处理的候选规模，实际有效数量由完整处理报告给出，不补造路线或标签。

全量报告保存每例身份、来源日志／会话、特征哈希、有效性及排除原因，并统计城市、日志和驾驶行为覆盖。检查直行跟驰、停车起步、换道和转弯等原任务材料；标签稀少时结合真实轨迹核查，不将无标签直接解释为无该行为。

无法获得模型原始训练全集时，使用现有可获得的原任务数据扩大保持覆盖，并以冻结原模型提供功能参考；不要求先重建完整原训练集才能开展修复。

### 2.2 成功保持基库

6,500 个实例按来源分为：

- **2,600 个**未经搜索的长尾生成实例；
- **2,600 个**自然生成实例；
- **1,300 个**Train／Val 来源的经验自然实例。

只有 \(\pi_0\) 全程无自车碰撞、无驶出道路且未触发现有停车条件的实例进入成功保持基库。来源、实例、世界资产和策略随机流均一致的已有合格记录直接复用，不重复执行。实际生成及筛选成本按实记录，不将候选数作为合格保持数。

基库与开发、最终集合隔离。真实执行过的成功邻居作为增量材料保存，记录其事故祖先关系，不挤占事故专家输入名额，也不虚增独立祖先数量。共同危险验证祖先的成功邻居只能用于验证。

保持材料通过原模型功能约束参与学习；不把原策略经物理跟踪器执行后的未来统一改写为规划监督真值。安全筛选只构造保持库，不改变 \(P_{\text{tail}}\) 或 \(Q_{\text{natural}}\) 的最终采样规则。

经验自然 **Test 暂停新增评价**，已有 Test 及历史报告保留。这里的经验保持材料来自 Train／Val，不使用暂停的 Test 集。生成集合的独立性指 ADS 阶段的实例及用途隔离；全量尾部建模涉及部分 highD Test 来源，不据此宣称全链源数据独立。

### 2.3 事故池全量利用与危险验证

从三方法共同 \(\pi_0\) 下的主搜索事故池合并去重，隐藏方法标签，使用固定种子、现有风险及归一化交互描述选定共同的 **32 个危险祖先**；优先保留祖先与交互状态差异。固定清单后，禁止这些祖先的全部后代和成功邻居进入任何方法的修复、保持或偏移补标。

其余主搜索发现的失效输入全部申请专家示范，按实例内容哈希去重。读取完整搜索结果，不以每分支 16 个档案代表或原 128 个输入上限截断学习材料。档案重测的重复记录不增加输入数；专用分支检查点只用于诊断，不进入修复池。

每个输入最多验证 **128 个**既有参数化专家候选。从相同初态和外生随机实现开始，让 NPC 正常闭环响应；仅全程无自车碰撞、无驶出道路且未停车的合格成功执行产生原生监督标签。保留较小意图改变与平顺性优先的既有专家选择原则。没有合格示范的事故仍保留，报告专家覆盖缺口，不产生正向标签。

现有正式首轮的 MC、标准子集、本文分别有 **160／215／450 个**方法内去重碰撞输入，来自 **160／112／98 个**祖先。实际修复数量须扣除共同留出祖先和无合格示范的输入。不同方法出现相同实例时共享核验通过的专家缓存，分别记录使用条目与实际生成成本。

### 2.4 开发与最终集合隔离

两类生成开发集合各 5,000 个，采用冻结原分布 IID 采样，不做对抗筛选或按结果补挑。原生开发使用全量有效的独立来源场景。危险开发集属于针对性检查，不用其命中率解释总体事故率。

训练入口拒绝所有开发／最终实例及其受保护谱系。偏移后缀继承原训练祖先和用途。开发、最终和修复采用不同采样命名空间；保留一个实验种子，不增加 ADS 多种子实验。

新版最终集合各新建 5,000 个实例，不将已分析的旧 2,000 个与新增 3,000 个拼接。配置和全部候选选择完成后冻结部署权重，再创建最终实例。所有策略共用实例、世界资产和对应策略随机实现进行配对。

## 3．训练组织与能力保持约束

### 3.1 有效 batch 与数据遍历

有效 batch 为 **128**，每次更新固定分配：

| 来源 | 样本数 |
|---|---:|
| nuPlan 原任务 | 64 |
| highway 成功保持 | 32 |
| 合格专家修正 | 32 |

微批次为 **8**，通过梯度累积完成一次有效更新。每项损失按实际有效 batch／来源计数归一化，不因微批次改变权重。保留 DP 原生去噪和周车预测监督；超过实际执行窗口的未来在输入构造与损失中均标为无效。

采样按场景／祖先打乱遍历。原任务和保持基库先完成场景覆盖再重开下一轮；事故先均衡祖先，再轮转其变体、查询点与帧。同一祖先有更多事故变体时不获得更大训练权重。每个有效事故示范均进入材料池，通过轮转实际访问，分别记录场景、祖先、查询点、标签帧的访问与重复次数。

正常完成 500 次更新，三类曝光分别为 **32,000／16,000／16,000 次**。完成前 250 次更新时，原任务抽样 16,000 次、保持抽样 8,000 次，在覆盖优先的采样器下均可遍历其基库至少一次。这里的曝光不是独立场景数量；早停时按实际计数报告。

有效 batch 128×500 的总曝光等于 batch 64×1,000，不能将其表述为训练量减半。扩大数据池后不自动提高学习率或增加更新次数。

### 3.2 原任务监督与功能保持

模型只更新当前 DP 的最后一个 DiT block 与输出层，冻结编码器、其他网络和归一化统计。三类信号分别承担：

- 原任务真实轨迹监督：维持既有任务学习目标；
- 冻结官方模型和成功行为记忆：保持原有功能；
- 合格专家轨迹：纠正事故应对。

原模型在失败状态上的错误自车输出不作为保持目标。专家成功、标签跟踪成功与学习策略真正修复成功分别记录，避免用材料验收代替策略闭环结果。

对原任务和 highway 成功保持分别形成约束目标。设 AdamW 提出的实际参数位移为 \(\Delta\theta_0\)，对应保持梯度为 \(g_N,g_H\)，在冲突时采用 GEM 思想求接近原更新的可行位移：

\[
\min_{\Delta\theta}\|\Delta\theta-\Delta\theta_0\|^2,
\qquad
g_N^\top\Delta\theta\leq0,\quad
g_H^\top\Delta\theta\leq0.
\]

约束检查包含 AdamW 预条件和权重衰减的实际参数变化，不只投影原始梯度。保持梯度为零时不提供有效方向约束；继续检查固定噪声下的功能偏移，并对部署 EMA 做闭环验证。一阶保持约束服务于训练控制，实际驾驶保持效果由独立结果检验。

教师冻结、学生梯度、冻结参数、优化器、raw 训练权重和部署 EMA 分别核对；拒绝候选后恢复完整接纳状态。学习率不高于现有 \(10^{-5}\)，采用衰减更新。

## 4．一次修复、状态补标与模型接纳

### 4.1 两段更新与一次有限补标

修复总上限为 **250＋250 次梯度更新**：

**初始全量事故材料 → 第一段更新 → 开发检查 → 一次有限偏移补标 → 第二段更新。**

第一段通过继续开发条件后，只在修复训练实例上采集候选实际到达的状态；不读取开发或最终实例，不重新搜索 Flow／Diffusion 潜变量。依据已有风险评分，在碰撞或风险峰值前约一秒选取尚未失效、具有剩余执行窗口的决策点。每方法最多 96 个查询点，每祖先最多一个，先覆盖不同祖先。

每点最多验证 128 个专家候选。所有候选从相同查询快照恢复，NPC 继续正常响应；成功后缀形成标签，无法纠正则记录缺口，不通过无限前移查询增加预算。第二段聚合初始与后缀材料，仍保持 64／32／32 的来源配额，不只训练新困难状态。

当前世界模型已有 `snapshot()`／`restore()`，覆盖物理状态、历史、参考索引、车辆状态和 NPC 接管控制器运行状态。后续复用此能力，在 ADS 层补齐轨迹跟踪器、完整策略历史、决策步、已执行控制和随机流上下文。

快照绑定原实例、资产和外生随机实现。软计划及响应随机量维持绝对时间索引，专家候选启动时刻相对查询时刻计算。后缀继承训练谱系，不能作为新增独立先验实例，也不将原失败后缀当作正确未来。

### 4.2 开发验证与候选选择

仅检查原模型及累计 **250／500 次更新**候选，共用全部固定开发数据。500 表示累计更新上限，不是两段各 500 次，也不是开发场景数量。

候选相对原模型及当前接纳参考须满足：

- 两类生成验证的碰撞、驶出道路和停车计数不增加，进度至少保持参考模型的 **98%**；
- 全量有效原生开发场景上的平均原生监督损失、规划 ADE／FDE 不高于原模型，并报告城市和行为分组结果；
- 长尾生成或危险验证出现实际安全改善；
- 分别记录修复了多少原事故、原成功场景新增多少事故。

原生离线比较采用共同固定随机实现，保持前向与评估模式一致。官方原模型结果按实例、配置和权重身份共享缓存。原生离线指标不替代 nuPlan 城市闭环结果。

合格候选依次优先碰撞更少、原成功场景新增事故更少、功能偏移更小的模型；仍并列时优先较早候选。进度作为保持门槛，不以最大进度驱动模型选择。

开发安全回退时停止该路径，恢复接纳参数、EMA 和优化器状态。第一段仅在安全与任务保持条件通过后继续，不要求必须已经完成全部改善；最终接纳仍需实际安全改善。没有合格候选则保留原模型。各方法使用相同上限、停止与选择规则，记录实际消耗。

### 4.3 最终配对评价与原生交付

两个最终生成集合各 5,000 个实例，比较原始与三个最终模型，共 **10,000 个不同实例、40,000 次完整执行**。主要报告配对碰撞率差及沿用的 95% 配对区间，同时分别报告驶出道路、停车和进度。多策略重复执行不增加独立场景数。

最终评价不参与模型重选、权重调整或补挑场景。每方法导出一个固定的原生增强权重及必要配置，核对官方加载器回读、参数与输出一致性。三个方法的模型用于研究比较，不按数据集切换部署权重。

nuPlan 城市闭环继续由用户手动执行，保存共同场景、原始／增强权重哈希及原生指标，独立于 highD 生成结果。

## 5．比较口径、成本与实施验收

### 5.1 两组主实验

**搜索效率：**MC、标准子集与本文方法从共同 \(\pi_0\) 开始，各执行 5,000 次实际闭环测试，比较不同事故输入、事故祖先及随实际执行成本变化的发现曲线。

**修复效果：**学习器、有效 batch、更新上限、保持数据和模型选择规则相同，比较修复后在共同最终实例上的表现。所有方法均使用其全部可用事故材料申请示范。

专家成本随实际发现及合格材料数量变化，分别记录，不将完整流程称为等总成本比较。发现更多变体、取得更多示范和最终安全改善分别给出证据；不将其中一项代替其他结论。

### 5.2 成本账本

| 项目 | 预算或核算规则 |
|---|---|
| 搜索 | 三方法各 5,000 次，共 15,000 次；专用检查等包含其中 |
| 初始专家 | 每个去重输入最多 128 次候选验证；现有三方法 825 个使用条目在扣除验证祖先和共享缓存前，上限为 **105,600 次** |
| 偏移专家 | 三方法各最多 96×128，共最多 **36,864 次后缀候选验证** |
| 生成开发验证 | 原模型加最多六个候选，共最多 7×10,000＝**70,000 次完整执行** |
| 最终生成评价 | 四个模型，共 **40,000 次完整执行** |
| 其他 | 保持库生成与筛选、危险开发验证、原生离线前向、候选补标采集和梯度约束计算单列 |

825 是三方法各自去重后的使用条目之和，不表示跨方法没有重复。实例、专家规则和资产一致时共享缓存；生成一次和被多个方法使用分别计数。

完整执行与专家后缀执行分列，同时记录物理步数及时间，不假定一次短后缀等价于一次完整六秒闭环。区分既有数据／缓存的历史成本、本版新增成本和累计成本。可核验一致的既有首轮搜索与合格示范优先复用，不为重新计数而重复执行。

### 5.3 后续实现验收

1. **全量与来源。** 全部训练及原生验证候选均有结果，无数量截断；有效数、排除原因、城市／行为覆盖和会话隔离可核查。
2. **危险谱系隔离。** 共同留出的 32 个危险祖先、全部后代及成功邻居不进入任何方法的修复或补标；生成开发与最终实例同样拒绝进入训练。
3. **学习材料。** 全部合格事故示范进入材料池并实际被访问；失败示范不产生正向标签，成功邻居不挤占事故名额。
4. **均衡与曝光。** 原任务／保持完成场景覆盖后再遍历；事故按祖先均衡；相邻帧、变体及补标后缀不虚增独立场景数。
5. **更新约束。** batch 128、微批次 8 的损失及梯度累积正确；实际参数位移满足有效保持约束，冻结参数与归一化不变。
6. **状态与标签。** 快照恢复后的固定控制前缀可重放，NPC 接管及随机索引一致；策略输入因果、未来有效性掩码正确。
7. **候选与交付。** 250／500 累计更新计数、开发停止、EMA／优化器回滚和原生导出回读正确；最终只交付固定权重。
8. **成本与历史。** 所有新增世界执行、后缀、监督曝光和缓存复用完整记录；不覆盖既有实验协议、结果、资产或权重。

先完成这些接口与材料验收，再制定执行清单。本文档中的扩大规模与新机制均为待实施设置，不据此将历史结果重记为新版实验。

### 方法依据

- [Learning without Forgetting](https://arxiv.org/abs/1606.09282)：原模型功能保持的依据，支持在原训练材料不完整时利用冻结教师。
- [Gradient Episodic Memory](https://proceedings.neurips.cc/paper/2017/hash/f87522788a2be2d171666752f97ddebb-Abstract.html)：基于保持材料约束新任务更新的依据；本方案检查实际参数位移。
- [DAgger](https://proceedings.mlr.press/v15/ross11a.html)：在学习策略实际到达状态上聚合纠正材料的依据；本方案只采用一次有明确预算的补标。
